# Authorized recovery of six unknown Astra outcomes

Six original GPT-6 Astra requests ended with `ConnectionResetError` after dispatch. Their markers and transport logs were retained, and none had a captured response, provider response ID, or recorded generation. This differs from the earlier explicit HTTP 520 non-outcome. The six original calls may have completed or incurred charges remotely; the available evidence cannot determine either fact.

The user explicitly chose to retry these six held calls once. The parent task bound that answer to the reviewed proposal, checked the six original marker/request/event identities and all 9,534 already recorded generations, and activated the operational helper. The helper completed six stock reconciliation releases and published the existing controller's resume control. This archive records that bounded recovery; it does not claim that replacement generation, the remaining 66 slots, or the final 9,600-slot evaluation has finished.

## Scope and preserved evidence

The exception names exactly six original attempt IDs in `contract.py`. It permits one explicit release of each original unknown outcome. Models, prompts, high reasoning effort, the 8,192-token cap, schedule identities, verification budgets, Lean engine, frozen Python package and recorded responses remain unchanged. The existing transport retry policy still applies. A replacement that itself becomes uncertain remains held and is outside this approval.

`recovery_helper.py` requires a proposal-bound approval record citing the actual human answer. A pending template or elapsed time is insufficient. Each original marker is rechecked under the unchanged stock file lock before stock reconciliation appends its release amendment and tagged transport event. A live lock, changed marker, saved capture or recorded response stops release. Partial stock amendment/log states can be completed safely after a crash. A proposal-bound resume control is published atomically only after all six releases finish; an existing pending/applied control prevents a second publication. The helper does not make a direct API request, but activation resumes the already-authorized credential controller.

The approval file is an operator's evidence record, not cryptographic human authentication. The parent must verify its reference and answer against the trusted conversation. The frozen proposal, approval, original transport evidence, marker hashes and baseline inventory remain private operational prerequisites. They are not included in this source archive, and the archive starts nothing.
