# Lean validation and extraction engine

`lean/Evaluator.lean` is a tested source driver for the exact toolchain declared by the environment manifest. Launch it through the isolated Python runner. A manual trusted-fixture invocation is:

```text
<manifest lean_binary> --run lean/Evaluator.lean request.json result.json
```

`PATH` must start with the pinned toolchain's `bin` directory and `LEAN_PATH` must contain the manifest's compiled-library directories. Lean's `findSysroot` consults the runtime path. Mixing the global default Lean with the pinned binary can produce incompatible `.olean` headers. No project or dependency is modified by the driver.

## Interface

The request object contains `imports` (module names), optional `import_specs` descriptors, `target_name`, `binders`, `proposition`, `proof`, `context` (trusted commands, default empty), `forbidden_declarations`, `permitted_axioms`, `max_heartbeats`, and `mode`. Modes `validate` and `extract` are checked in separate fresh processes by the Python runner. `extract` repeats validation before computing the graph. Optional `expand_modules` marks compiled evaluator context modules for expansion. Optional `max_graph_nodes` bounds graph extraction (default 100,000). `verify_histogram_cache` requests a development comparison against uncached counting and should remain false for benchmark runs. A missing or non-string `proof` is an `evaluator_error`, a checker input error; an empty string is still parsed and fails as `parse_failure`. Optional `replay_max_heartbeats` (raw kernel heartbeats) and `replay_max_rec_depth` override the kernel replay limits described below. They are testing and diagnostic overrides that the Python runner never sends. As in Lean, 0 means no limit; any other present value that is not a natural number below 2^64 is an `evaluator_error`.

`import_specs` entries use `module`, `is_meta`, `is_exported`, and `import_all`, corresponding to Lean.Import. Missing Boolean fields default to false, true, and false respectively. Descriptor module order must equal `imports` exactly; mismatches and malformed flags are environment errors. When descriptors are absent, the original string-list behavior is unchanged. `resolved_imports` records the flags actually loaded. The reconstructed Real.Pow fixture preserves its `public meta import Mathlib.Data.Nat.NthRoot.Defs` header; meta imports control transitive IR loading.

The proof is parsed as one complete Lean `term`; any remaining non-comment text is a parse failure. Its syntax is inspected for executable metaprogramming forms before elaboration. The entire fixed theorem is also parsed to end of input. The trusted target is separately elaborated from identical binders and proposition in the pre-proof environment. Its temporary signature axiom is never visible to the candidate. Each elaboration creates its own statement auxiliaries, such as the matcher of a `match`, pattern `fun` or `if let`. The trusted fork's auxiliaries are kernel-checked into the comparison environment first, so a candidate declaration cannot take their names. The candidate's header auxiliaries are checked in next, and the two types are then compared there.

The `context` is elaborated once and its command state, open namespaces and scoped variables are retained. An original source prefix can therefore reconstruct a Mathlib task. Context is evaluator-owned trusted input; never fill it with a model response. A compiled-prefix module can instead be imported and listed in `expand_modules`.

Before elaboration, actual kernel-environment declaration Names are scanned against `forbidden_declarations` labels without reparsing those labels. Every entry must be absent from the trusted runtime environment. A present original theorem or alias fails as `forbidden_environment`, even if the submitted proof would not use it. The final dependency closure is independently checked against that set.

## Validity evidence

The engine checks the final target against the separately elaborated trusted type, rejects unresolved metavariables and traverses all dependencies in **all packages** for axioms and forbidden names. This validity traversal does not stop at the compression primitive boundary. `getUsedConstants` is used only for dependency reachability and kernel-replay ordering, never for weighted metric counts.

The default axiom allowlist is `propext`, `Classical.choice`, `Quot.sound`; the trusted run configuration may narrow or explicitly change that list. `sorryAx` is always rejected. Original `sorry` and `admit` syntax is rejected even if an unused local proof would otherwise disappear. Indirect use through a theorem or opaque value is detected by the transitive audit.

All root-reachable declarations created during candidate elaboration are replayed in dependency order from the pre-proof environment, extended only by the trusted statement auxiliaries, through `Environment.addDeclCore` with `doCheck := true`. The root is replayed using the independently elaborated original type. Each declaration gets the kernel budget `Lean.addDecl` derives from the same options (`max_heartbeats` × 1000) and recursion depth 10,000, and runs in a fresh task. The kernel heartbeat counter is per thread and restarts only when a task starts, so a declaration is never charged for earlier kernel work. During replay, a kernel deterministic timeout is `verification_timeout`, excessive memory or deep recursion is `verification_resource_limit`, and any other rejection is `kernel_replay_failure`. A trusted statement auxiliary that fails replay is an `environment_error`. Generated definitions, theorems and opaque declarations are supported. Generated inductive declarations or recursive cycles in candidate auxiliaries produce a replay failure instead of silently bypassing checking. The actual `as_aux_lemma` fixture creates an auxiliary theorem and passes replay.

Success output includes `validity_status: success`, `kernel_replay: true`, checked `axioms`, the resolved `root`, `candidate_declarations`, `statement_auxiliaries`, and a proved-type fingerprint. `statement_auxiliaries` lists, sorted, the declarations that the two statement elaborations add: the trusted fork's, besides its signature axiom, and the candidate header's, such as `evaluation_target.match_1` or the `evaluation_target._proof_1` of a `by omega` inside the statement. A statement can also realize declarations that its elaborated type never mentions: the equation and matcher lemmas of a nested `by simp [f]`, the rest of the `f.eq_1` family when it names `f.eq_1`, or the lemmas a nested `split` realizes about the statement's own matcher. To find all of the candidate header's, the engine elaborates `axiom <target_name> <binders> : <proposition>` in a further fork of the pre-proof environment once every check has passed. A candidate declaration is listed exactly when that fork adds one with the same name, universe parameters, type and value, or when the replayed candidate type reaches it. This also decides global names that both forks can realize, such as `f.eq_1`: if a dotted `target_name` elaborates the candidate's statement in another namespace, a lemma that only the trusted statement and the proof realize remains a helper. The fork affects no other output; if it reports an error, `statement_auxiliaries` is null. The candidate's statement auxiliaries also appear in `candidate_declarations`, but they come from the fixed statement, not the proof. Proof helpers are the other non-root candidate declarations, including lemmas a tactic in the proof realizes about a statement matcher, such as its splitter. Failures retain distinct statuses for syntax, elaboration, target mismatch, forbidden environment/dependency, axioms, and replay. Wall-clock timeouts and process resource failures are classified by the process runner.

Success output also includes `heartbeats`. Its `raw` object holds deltas of `IO.getNumHeartbeats`, the per-thread count of small allocations that the elaborator's `maxHeartbeats` limit reads: candidate `elaboration`, `kernel_replay`, and their `total`. `max_heartbeats_units` divides each by 1000, the unit of `max_heartbeats`. Lean's frontend elaborates the candidate in a task on a pooled thread whose counter keeps earlier tasks' counts, so a reading on the engine's own thread would miss the work. Before imports, the engine therefore registers a wrapper around Lean's builtin declaration elaborator under that elaborator's own name, which leaves incrementality and info trees unchanged, and the wrapper reads the counter on the elaboration thread. The candidate's reading includes the elaborator's own kernel check, because `Elab.async` is off, but not linters. Kernel replay adds readings taken inside each replay task on both sides of its check, for the candidate's declarations only; the replay limits are converted before the task starts, so the readings cover the check alone. The kernel enforces its budget with a separate counter, so replay readings are not in that budget's units. Neither reading is bounded by or comparable with `max_heartbeats`: the elaboration reading includes the elaborator's own kernel checks, which run against that separate budget, and either reading can exceed `max_heartbeats` in a check that passes. For example, the `omega` fixture of `tests/test_heartbeats.py` passes when rerun at `max_heartbeats` 50, reading 124.8 units of elaboration and 70.8 of kernel replay, and fails at 45. Failure records carry no heartbeats, and `heartbeats` is null if the declaration elaborator was not reached. Rerunning all 250 references through the development runner with heartbeat reporting, before it was combined with `statement_auxiliaries` and the replay-limit overrides, reproduced every stored validity status, token span, graph hash and metric; for 24 of them the source before heartbeat reporting gave the same engine output apart from `heartbeats`, at comparable wall time. The validation and extraction runs of each reference reported identical kernel replay readings and elaboration readings within 0.11% of each other. With the current source, those 24 references and the 10 smoke references, checked by two parallel `verify-references` workers, reproduced the stored evidence again. Their engine output matched the heartbeat rerun's apart from the new `statement_auxiliaries`, empty for every reference, and kernel replay readings 5 to 20 raw heartbeats lower, since the limit conversions are no longer measured. These reruns are not committed evidence.

`trusted_type_source`, `universe_parameters`, and `trusted_telescope` expose the elaborated signature for dataset preparation. The telescope contains named binders, binder visibility, each type in its preceding local context, and the final proposition. Reparse and verify any reconstructed signature; pretty-printed text is an aid, not a round-trip guarantee. Scoped variables are not automatically charged to source `W_S`, so production dataset preparation must materialize all intended explicit binders before freezing tasks.

## Token accounting

`source_tokens` contains the exact assembled declaration, UTF-8 byte spans, `W_S`, `W_B`, `W_full`, proof offset, and policy name `lean_original_leaf_spans_v1`. Counts come from original leaf atoms and identifier/literal spans, before elaboration or macro expansion. Repeated identical source spans are counted once. Whitespace, comments, and synthetic syntax do not count. This includes `/-- -/` doc comments, which Lean parses as syntax (for example on `let rec`). The fixed theorem keyword, evaluator target name, signature/body separator, and declaration colon are excluded from `W_S`/`W_B` but retained in `W_full`.

Lean normalizes CRLF while parsing. The extractor maps normalized positions back to the original input's UTF-8 byte offsets through a table built in one pass; the original source is preserved. Isolated carriage returns remain parser errors. The fixtures cover qualified names, strings, numerals, Unicode notation, comments, renaming, and CRLF.

## Weighted graph

Each graph node includes `name`, `owner_module`, `primitive`, separate `signature` and optional `body` occurrence histograms, type/body diagnostic hashes, histogram measurement status, expression node counts, literal bytes, and null source counts for declarations without independently submitted source. The root's source costs are recorded once in `source_tokens`; generated auxiliaries never receive invented source costs.

Ownership comes from the environment's module index. Mathlib-owned declarations, current evaluator declarations, and explicitly listed evaluator modules are expanded. Other frozen modules are atomic boundary nodes. The distinguished `@Sort` is atomic. The result is **paper-aligned**, not a numerical reproduction of an author implementation.

Every occurrence of `.const` and `.sort` is counted, through applications, binders, lets, metadata and projections. Variable and literal occurrences add no primitive references; literal sizes and complete expression nodes are separate diagnostics. Counting visits each distinct subexpression once and passes every parent's occurrence count to its children, so repeated shared expressions retain their multiplicity at a cost linear in the shared expression graph. Literal sizes are exact decimal byte lengths, computed without decimal conversion. `ConstantInfo.value? (allowOpaque := true)` retrieves theorem and opaque bodies. Absent body remains JSON null; an existing body with no references remains `{}`.

Atomic boundary nodes have `histogram_status: atomic_boundary_not_expanded`, empty edge placeholders, null node/literal diagnostics, and an explicit `body_present` flag. Their empty placeholders are **not measured zero histograms**. Expanded nodes have `histogram_status: measured`; a measured absent body is distinguished by `body_present: false`. This avoids traversing irrelevant boundary bodies without misrepresenting missing data.

Graph traversal preserves actual Lean `Name` values (including numeric and private components), using deduplicated constant references only to discover graph nodes. Names are not reconstructed from display strings. Distinct names that collide under the exported text label cause an explicit extraction error.

The graph is the reachable closure of the root; `candidate_declarations` separately inventories all newly generated declarations, including unused auxiliaries. An unused auxiliary does not affect root recursive expansion; its syntax remains charged to the whole submitted proof source. Missing constants and missing module ownership are extraction errors. Graph cycles, zero-reference nonprimitive nodes, exact integer arithmetic and ratio availability are handled by the Python metric engine.

Expression debug strings and pretty-printed binder names can contain hygiene identifiers and are not suitable for comparing separately elaborated signatures. Dataset freezing should independently kernel-check definitional equality of the old and materialized signatures, then revalidate the private reference.

The diagnostic `type_hash`, `value_hash`, and `proved_type_fingerprint` are Lean's noncryptographic structural expression hashes. They are not collision-resistant content addresses. The persistent graph cache does not key only on those values: it uses SHA-256 over the complete environment identity, boundary policy, declaration name, diagnostic hashes, and complete weighted histograms. Conflicting histograms under the same frozen node identity are rejected. This cache reuses exact metric inputs; it does not establish expression equality or proof validity. The Python runner separately records SHA-256 of the complete exported graph, source, engine and environment.

## Isolation and limits

The engine's executable-syntax denylist is defense in depth; it is not a general sandbox or a proof of absence of all executable elaborator behavior. Ordinary Lean tactics execute trusted code. The production runner must enforce no network, a sanitized process environment, a read-only library and no evaluator-secret access. Do not run arbitrary model responses directly through the manual invocation above.

The engine source uses an `unsafe` entry point only for Lean's required `enableInitializersExecution` when loading trusted library extensions. Submitted proof values must still pass the independent kernel replay and axiom gate. Module source and compiled libraries are part of the trusted computing base.

Metric extraction errors never alter an already stored validation success. The extractor's own outcomes are final: an extraction timeout or resource limit, a graph error, or an engine verdict reported in extract mode leaves compression unavailable while retaining correctness success. A checker or infrastructure failure of the extraction process is not such an outcome: a crash without a result, an unreadable result, an `evaluator_error`, a Docker or container-cleanup failure, or an engine edited during extraction. Like one in verification, it is logged as a checker incident, no record is written, and the slot or reference stays pending until a rerun measures it. This narrows the plan's "valid proof with extractor failure" row to the extractor's own outcomes. The frontend's structured error output does not itself distinguish every resource condition; outer process budgets remain authoritative.

## Executed fixtures

`tests/test_lean_integration.py` runs real Lean proofs against the manifest-selected binary. It covers ordinary and meta import descriptors; internal numeric and non-roundtrippable guillemet declaration names without text round-tripping; source spans; invariance under comments, whitespace and local renaming; UTF-8 and CRLF positions; doubled references; theorem and opaque values; generated auxiliaries; cached/uncached histograms; direct and indirect admissions; custom axioms; wrong propositions; replacement declarations and multiple responses; imported forbidden declarations; restricted metaprogramming; and valid proofs with graph extraction errors.

`tests/test_lean_engine_fixes.py` adds regressions that failed on engine `83da0074`: kernel-heavy proofs within Lean's replay budget, `match`, pattern `fun`, `if let` and nested-`by` statements with their statement auxiliaries, a candidate matcher reusing the trusted auxiliary's name, doc comments, missing or non-string proofs, a 1000-step CRLF proof, a heavily shared `ring` term and huge numeric literals. It also covers the restricted-syntax denylist beyond `run_tac`, and a proof valid only for a different matcher statement, which the type comparison itself rejects as `target_mismatch`. Through the replay overrides it checks a budget that only per-declaration tasks satisfy, and the timeout, resource-limit and trusted-auxiliary replay statuses.

`tests/test_statement_auxiliaries.py` adds regressions that failed on engine `b10e7972`. Declarations that a statement realizes without its type mentioning them must be statement auxiliaries: those of a nested `simp [f]` over a context or imported definition, of a named `f.eq_1`, and of a nested `split` over the statement's own matcher. The same declarations realized by a proof, and a proof's `let rec`, must remain helpers, as must a lemma that a proof and only the trusted statement realize under a dotted target name. Through the runner under the macOS development sandbox, `helper_count` must be 0 for the nested `simp [f]` statement with an `rfl` proof and 6 for a `simp [f]` proof of `f 0 = 1`; a null list keeps every declaration in the count.

`tests/test_heartbeats.py` checks that a trivial proof records few heartbeats, that `omega` records many more during elaboration, and that `decide +kernel` over a 3000-element list records more than a million raw heartbeats in each phase. Each phase must keep its own reading: a trivial proof's elaboration exceeds ten times its replay, and `omega`'s elaboration exceeds its replay. For a `match` statement, kernel replay must read 2646 raw heartbeats on the pinned toolchain, which excludes the trusted statement's auxiliaries. It also checks that the runner copies the reported total into `resources.heartbeats_used` and that the analysis summarizes it.

The generic unit suite skips these fixtures only when the pinned local runtime is unavailable. `LEAN_COMPRESSION_ENVIRONMENT` names the environment manifest that supplies that runtime (default `configs/environment.local.json`), and `REQUIRE_LEAN=1` turns the skip into a failure. The delivered local environment executed them; they are not mocked theorem-checking results.
