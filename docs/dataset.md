# Dataset collection and readiness

The collection contains **250 candidate tasks**, with the proposed numerical quotas: 50 pilot tasks and 200 main tasks, 10 pilot and 40 main tasks in each of five domains. Each main-domain group contains 30 reconstructed library tasks and 10 authored tasks. The pilot contains 40 library tasks and 10 authored smoke tasks. Numerical coverage does not establish that this is a frozen, representative benchmark.

`data/public/tasks.jsonl` is the combined task manifest. The public component files are `smoke.jsonl` (10), `library_candidates.jsonl` (190), and `fresh_main.jsonl` (50). References are stored separately in `data/private/references.jsonl` and the corresponding component reference files. **Do not send private reference files or whole task objects to a model.** A prompt should use only the approved imports, fixed premise excerpt, explicit target and chosen condition. The trusted `context` is evaluator input, not automatically approved model-visible input.

## Reconstructed library tasks

Each record identifies its Mathlib source module, declaration, line, full source hash and reconstruction policy. The supplied imports are the imports from that source file. `import_specs` preserves their order and the original `is_meta`, `is_exported` and `import_all` flags; the engine verifies that their module order matches `imports`. The target module itself is not imported. The trusted context reconstructs source preceding the target, including previous declarations, local notation, public sections and open namespaces. Module headers and imports move to the evaluator's import mechanism; target attributes and target documentation are excluded. The target is renamed into the evaluator namespace. Source excerpts retain Mathlib copyright notices; its license is included as `data/public/LICENSE-Mathlib`.

This is a source-based reconstruction, not permission to import the completed target module. The `forbidden_declarations` initially contains the resolved original target. It must be extended when alias and dependency audits identify additional forbidden names. A transitive dependency audit should enforce this set for generated proofs. The original target module's later declarations are absent by construction.

The original source signatures could depend on surrounding section variables. These implicit section parameters have now been materialized from Lean's trusted telescope, preserving the original written binders and proposition. A separate trusted comparison process elaborates the original and materialized declarations, aligns their universe parameter lists, and calls `Kernel.isDefEqGuarded` on the types. The original reference proof is then replayed under the materialized signature without comparison helpers. The comparison source and results are private evidence. This avoids relying on pretty-printed type strings or hygiene-sensitive expression hashes as equality checks.

`premise_context` contains the complete predecessor source plus required universe declarations, excluding evaluator target-absence assertions, with one exception: earlier proof text that gives away the target's private reference by a rule of the answer-access screen (see the Python interface below) is shown as the neutral placeholder `/- proof omitted -/`, keeping declaration statements, attributes and the data a target unfolds. Rows 417-424 of the amendment log (2026-10-12) did this for 8 tasks whose prompt contained the reference up to whitespace in at least 15 characters: `lib_algebra_groups_pilot_group_basic_02`, `_06` and `_08`, `lib_analysis_inequalities_main_convex_function_06`, `_08` and `_10`, and `lib_sets_logic_main_equiv_basic_04` and `_10`; in `equiv_basic_10` only the `right_inv` proof field of the definition `subtypePreimage` is replaced. Rows 686-717 (2026-10-12) did it for the 32 tasks on which the widened screen flags anything, one row per task from its earlier `premise_context` to its current one; every hit was reviewed as a true copy of the answer. In 24 of them the whole proof of one preceding theorem or lemma is replaced: `lib_algebra_groups_pilot_group_basic_04`, `lib_algebra_groups_main_commute_basic_03`, `_04`, `_06` and `_10`, `lib_algebra_groups_main_units_basic_03`, `_07` and `_10`, `lib_number_theory_pilot_nat_basic_04`, `lib_number_theory_main_gcd_basic_05`, `_06` and `_09`, `lib_number_theory_main_numbertheory_divisors_02` and `_09`, `lib_analysis_inequalities_pilot_field_basic_02` and `_03`, `lib_analysis_inequalities_main_pow_real_09`, `lib_analysis_inequalities_main_log_basic_03`, `lib_sets_logic_pilot_set_basic_02`, `lib_sets_logic_main_logic_relation_05`, `lib_sets_logic_main_equiv_basic_02`, `_04` and `_05`, and `lib_linear_algebra_combinatorics_main_basis_defs_10`; in `pow_real_09`, `equiv_basic_02` and `_04` the copy was a term or a tactic inside that proof. In 6 the whole proofs of two preceding theorems or lemmas are replaced: `lib_algebra_groups_main_units_basic_08`, `lib_analysis_inequalities_pilot_field_basic_06` and `_07`, `lib_analysis_inequalities_main_convex_function_09` and `_10`, and `lib_sets_logic_pilot_set_basic_03`. In `lib_sets_logic_main_equiv_basic_09` and `_10` the definition `subtypePreimage` keeps its data: only the Prop-valued proof component of its `invFun` field is replaced, together with the `right_inv` proof field in `equiv_basic_09` and the whole proof of one preceding theorem in `equiv_basic_10`. A placeholder stays on the `:=` line unless that line would exceed 100 characters, when it starts the next line indented 2 spaces deeper than its declaration or field; a proof that started on its own line keeps that line's indentation, and a replaced proof component keeps its place in its anonymous constructor. `premise_context` is display-only and never compiled, so it need not be valid Lean; the Lean inputs and `verification_request_hash` are unchanged, and the references of all 37 amended tasks were re-verified with engine `83da0074` with identical metrics and graph hashes (the 32 of rows 686-717 once each, in one sequential run with one summary). The 68 task rows changed by rows 417-484 are kept in their earlier form in `data/private/tasks-before-answer-access-and-audit-amendment.json` and the 32 changed by rows 686-717 in `data/private/tasks-before-near-verbatim-amendment.json`; each amended row's `provenance.premise_policy` states the rule it was amended under (the original text, that of rows 417-424 or that of rows 686-717). This gives models coherent local definitions, notation and scopes. It includes earlier library proofs, and on the current data the answer-access screen lists no task. The largest trusted library prefix is under 7 KB. The same fixed bytes are used for every condition. The earlier excerpt policy is preserved in the amendment log and `library-before-premise-context.jsonl`; this prompt-only revision did not change runtime imports, signatures, contexts or proof bodies.

A screen that lists no task does not establish the absence of answer access, and no further text was elided after rows 686-717: the remaining cases are left to the pending human answer-access audit. They are listed, with task IDs, `premise_context` lines, the visible text, edit counts and the independent verifier's Lean records, only in the private file `data/private/answer-access-review.json`, which also holds the screen's own near-miss list; public documents give their counts alone. By category, on the current data: in 8 tasks the independent verifier found a proof that Lean accepts for the target verbatim in the prompt or within the screen's edit bounds of prompt text that is not near the stored reference; in 5 tasks prompt text of a kind amended elsewhere lies just outside the bounds; in 10 tasks generic automation shown in a preceding proof is accepted verbatim; 15 tasks show analogous proofs farther away; 13 tasks show, by design, the statement of a lemma that their reference applies; 25 tasks have exact matches below 9 characters, all generic shapes; and in 10 tasks only fragments of larger terms come near. These categories cover 76 tasks, and a task can fall in several. The screen's own near-miss pass lists 20 tasks with proof components just outside its bounds and 15 with near copies at positions that are not proof components (statements, parenthesized arguments, application heads and partial terms). Paraphrases and proofs farther from the reference are not detected. Documentation, code and tests never quote a private reference proof (library prompts do show earlier library proofs, as described above): `tests/test_public_answer_leaks.py` checks that README.md, `docs/`, `src/` and `tests/` contain no private proof of at least 9 normalized characters, and that the readiness report the README command builds from the committed evidence contains none and does not name the tactic of a one-tactic reference. Two exposures remain by design. The compile-only `context` field of each public task row, which the model never sees, keeps the original Mathlib source before the target, so it still contains every elided text and, for 9 tasks, the task's own reference proof; answer-access rules concern the model-visible prompt, and these library proofs are Mathlib's own. The readiness report is internal curation material: it is built from the private evidence, and its per-task source-shape labels and `reference_proof_in_prompt` flags reveal facts about private answers (a `literal_reflexivity` label, for example, gives the answer's form), so it must not be published with the benchmark. Git history also keeps earlier prompts, documents and readiness reports that exposed answers; publish the benchmark from a fresh snapshot without history.

## Authored tasks and novelty

The 60 authored statements combine assumptions or ask related consequences, with a short rationale in each provenance record. They are not generated by renaming a theorem or substituting a sequence of constants. They include algebraic consequences, divisibility and remainder combinations, real inequalities, set and logic constructions, linear maps and finite sums/products.

“Fresh” here means authored for this collection. It is **not** a claim that an equivalent statement is absent from Mathlib, public mathematics or model training data. Exact/equivalent-statement screening remains part of the answer-access audit. Many tasks are easy controls and use existing automation effectively.

## Sampling and family limitations

The library collection starts from early suitable declarations in 20 selected source modules. It is not a random sample of Mathlib and does not yet meet a defensible depth/length stratification. Source-length strata and authored-task difficulty labels are provisional; measured reference depth and length must inform the final strata before model outcomes are available.

Library families initially group source modules; authored families identify the construction used. Independent review led to replacement of two smoke problems and one main problem with construction overlap across pilot/main, replacement of two library aliases whose equivalent theorem was already available, and merging of related main-task families. The new conditional-monoid smoke problem is grouped with its related pilot library family. These changes precede model generation and are recorded with prior tasks/proofs in `data/private/dataset_amendments.jsonl`. Its rows 227-717, added on 2026-10-12 and also before model generation, hold the retroactive context records (227-416), answer-access premise amendments (417-424), authored audit annotations (425-484), archived-index corrections (485-541), retroactive binder records (542-685) and the near-verbatim answer-access premise amendments (686-717) described above.

Module separation alone cannot establish complete separation of related constructions. Broader cross-module and authored/library review remains pending, so `family_reviewed` remains false. Two merged main families cross domains: `main_two_step_discrete_gap` (`number_theory`, `linear_algebra_combinatorics`) and `main_injective_first_coordinate` (`sets_logic`, `linear_algebra_combinatorics`). Domain-stratified family resampling is appropriate only when the final families are nested within domains. Report the eventual number of independent families, not only 250 task rows.

The pilot may guide runtime, extraction and precision decisions. Do not tune task replacements or family groupings using main-model outcomes. Archive every preprocessing correction and pre-evaluation exclusion with its reason.

## Python interface

`load_tasks(path)` reads JSONL or a JSON task array (also accepting an object with a `tasks` array). `validate_manifest(tasks, enforce_quotas=False)` returns a list of structural errors; it does not raise on ordinary validation failures or assert Lean correctness. With `enforce_quotas=True`, it checks the complete 50/200, domain and main-origin quotas.

`validate_references(tasks, references)` checks the one-to-one private reference mapping. `readiness_errors(tasks)` returns unresolved readiness gates. Hash checks cover trusted context, premise excerpt, binders and proposition. Recompute these hashes only after an intentional, recorded revision.

`readiness_errors` never reports an empty manifest as ready. `validate_references` lists reference rows that are not objects with a string `task_id` instead of raising. `reference_in_prompt(task, proof)` reports whether a private proof's whitespace-normalized text occurs, at any length, in a prompt rendered by `prompts.messages()`, and returns `None` when it cannot run (no proof text, or a task that cannot be rendered). `screen_answer_access(task, proof)` applies the answer-access screen, which has three classes. An exact match is answer access from `ANSWER_ACCESS_MIN_CHARS` (15) normalized characters, the rule of rows 417-424, and from `SHORT_EXACT_MATCH_MIN_CHARS` (9) unless `generic_proof_shape` finds a shape that names nothing specific to the task: a literal reflexivity proof (`rfl`, `Iff.rfl`, `by rfl`, `by exact rfl`, `by exact Iff.rfl`); `SINGLE_TACTIC`, `by` and one identifier with no arguments (optionally ending in `?` or `!`), which accepts any identifier rather than a list of tactics because Lean can parse an identifier there only as a tactic name (a term after `by` needs `exact`), so the proof names no lemma, hypothesis or term; or a name bound by the target's own binders, which the statement shows anyway. A near-verbatim copy (`near_verbatim_matches`, for references of at least 9 characters that are not a generic shape) is a proof component of the premise context that few token edits turn into the reference while changing few of its name components. `proof_components` lists each declaration value (`declaration_values`: the text after a top-level command's first `:=` outside brackets, or after each `where` field's) and each term inside one that can stand as a proof by itself: an anonymous-constructor or tuple component, a rewrite or simp rule, a structure-instance field, a fun body, a `have`, calc-step or named-argument value after `:=`, the argument after `<|` or `$`, a `then` or `else` branch, a tactic block, each of its tactics (a line at the block's column, or after `;`, `<;>` or `·`) and a tactic's term (after `exact`, `exacts`, `apply`, `refine`, `refine'`, `use`, `from` or `using`). A parenthesized single term (an argument or a grouped function) and a declaration header (the statement of a lemma that a reference may apply, shown by design) are not components; a component never cuts a tactic block, and several tactics form one only as their whole block. Tokens (`proof_tokens`) are maximal runs of characters other than whitespace, brackets, commas and semicolons, so a name, a projection such as `h.1` and a notation such as `ℝ≥0` or `→*₀` are one token each; an edit inserts, deletes or substitutes one token or swaps two adjacent ones, so `foo_left b c` -> `foo_right c b` is two edits (the names in these examples are invented). A copy is at most `NEAR_VERBATIM_MAX_TOKEN_EDITS` (3) edits from the reference, or one per `NEAR_VERBATIM_TOKENS_PER_EDIT` (6) of its tokens where that allows more (for example 4 for a 24-token reference and 8 for a 47-token one), and the same comparison over name components (`name_components`: tokens split at `.` and `_`) changes at most `NEAR_VERBATIM_MAX_COMPONENT_FRACTION` (1/3) of the reference's components, rounded to the nearest whole component. That bound keeps the copy's content: `lefty_qux` for `righty_qux` changes 1 of 2 components and `Qux.foo_foo_bar_baz` for `Qux.foo_bar_quux_baz` 2 of 5, while `qux_ne_bar h` for `foo_ne_right h` (2 of 4), `Qux.corge _ _` for `Qux.grault_waldo_grault _ _` (3 of 6) and `rfl` for a longer proof are not copies. The bounds were set over all 250 tasks, every rendered field and every proof source: each hit on the rows saved before rows 686-717 was reviewed as a true copy, and the nearest exclusions are among the residuals counted above. Each match records the component's visible text (`snippet`), its `premise_context` line, whether it is a whole declaration value, both edit counts and the numbers of the reference's tokens and name components (`reference_token_count`, `reference_component_count`), closest first; it never holds the reference's own text or tokens. `answer_access_errors(tasks, references)` flags each task with an exact match that is answer access or a near-verbatim copy, and `validate-dataset --references` (in `readiness_errors`) and production `freeze` use it. In the readiness report, the `reference_proofs_absent_from_prompts` gate stays pending while `answer_access_screen` lists any task in `flagged_task_ids` (exact, 15 or more characters), `short_exact_match_task_ids` (exact, 9-14 characters, not a generic shape), `near_verbatim_task_ids` (with the closest match in `near_verbatim_matches`) or `unchecked_task_ids`; `generic_short_exact_match_task_ids` lists generic 9-14-character matches without blocking it. With the rows of `tasks-before-near-verbatim-amendment.json` substituted, the screen lists exactly the 32 tasks that rows 686-717 amended, and with those of `tasks-before-answer-access-and-audit-amendment.json` exactly the 8 of rows 417-424. Per-task `reference_proof_in_prompt` reports exact matches of any length. The JSONL readers end records only at line breaks (`\n`, `\r\n` or `\r`), so raw U+2028, U+2029 and U+0085 inside strings are preserved; decode errors cite `path:line`.

The structural validator detects duplicate task IDs, unsafe target/module names, malformed or reordered import descriptors, cross-split family IDs, accidental public reference fields, direct import of a target module, missing/incorrect quota counts, exact source signature duplicates and stale content hashes. It cannot determine logical equivalence, prove absence from pretraining or replace the Lean validity gate.
