# Dataset collection and readiness

The collection contains **250 candidate tasks**, with the proposed numerical quotas: 50 pilot tasks and 200 main tasks, 10 pilot and 40 main tasks in each of five domains. Each main-domain group contains 30 reconstructed library tasks and 10 authored tasks. The pilot contains 40 library tasks and 10 authored smoke tasks. Numerical coverage does not establish that this is a frozen, representative benchmark.

`data/public/tasks.jsonl` is the combined task manifest. The public component files are `smoke.jsonl` (10), `library_candidates.jsonl` (190), and `fresh_main.jsonl` (50). References are stored separately in `data/private/references.jsonl` and the corresponding component reference files. **Do not send private reference files or whole task objects to a model.** A prompt should use only the approved imports, fixed premise excerpt, explicit target and chosen condition. The trusted `context` is evaluator input, not automatically approved model-visible input.

## What has actually been checked

All 250 reference proofs have passed Lean checking using `leanprover/lean4:v4.34.0-rc1` and Mathlib commit `274ed6d67d9b226c557813b9ce437574cccdce11`. All 250 targets have explicit source signatures. The 190 reconstructed library references passed isolated engine validation, axiom/dependency auditing and kernel replay during signature materialization; evidence is in `data/private/library_signature_freeze/`. The 60 authored references first passed ordinary compilation; `smoke_reference_compile.json` and `fresh_main_reference_compile.json` retain the batch evidence, and `amended_smoke_reference_compile.json` and `amended_fresh_reference_compile.json` cover the replacement `smoke_ag_02`, `smoke_la_02` and `fresh_analysis_inequalities_08`. These files list task IDs without proof hashes; the batch entries for those three IDs concern the replaced versions. All 60 were later replayed in the isolated engine `83da0074` with kernel replay and axiom audit; those records are in `data/private/smoke-verified-final` and `fresh-verified-final`. Full metric-closure verification is accounted for separately from correctness.

The initial source-compilation triage is retained in `data/private/library_reference_compile.jsonl`, including failures from subsequently corrected prefix reconstruction. **For current verification status, use the per-task engine records listed in `data/private/reference-index.json` (all 250 at engine `83da0074`) and the readiness report built from them (`examples/dataset-readiness/`)**, not the earlier triage pass count. For the 8 premise-amended tasks described below, the index lists re-verification records in `data/private/premise-amendment-83da/`; the documented readiness command reads `library-verified-final`, whose earlier records for those tasks match the same `verification_request_hash` through the `library-before-premise-context.jsonl` snapshot. The `reference_verified` and `metric_closure_verified` flags read by `readiness_errors()` agree with that evidence. Amendment-log rows 425-484 (2026-10-12) set the 60 authored tasks' `audit.reference_verification_method` to `isolated engine replay and axiom audit, engine 83da0074` and add `independent_kernel_replay` and `axiom_policy_pass`, as on the library tasks; each row keeps the earlier text, which marked engine replay or audit as pending, as `old_audit` and cites its evidence file and SHA-256. The final library contexts assert that the original target is absent before the evaluator declaration. ## Reconstructed library tasks

Each record identifies its Mathlib source module, declaration, line, full source hash and reconstruction policy. The supplied imports are the imports from that source file. `import_specs` preserves their order and the original `is_meta`, `is_exported` and `import_all` flags; the engine verifies that their module order matches `imports`. The target module itself is not imported. The trusted context reconstructs source preceding the target, including previous declarations, local notation, public sections and open namespaces. Module headers and imports move to the evaluator's import mechanism; target attributes and target documentation are excluded. The target is renamed into the evaluator namespace. Source excerpts retain Mathlib copyright notices; its license is included as `data/public/LICENSE-Mathlib`.

This is a source-based reconstruction, not permission to import the completed target module. The `forbidden_declarations` initially contains the resolved original target. It must be extended when alias and dependency audits identify additional forbidden names. A transitive dependency audit should enforce this set for generated proofs. The original target module's later declarations are absent by construction.

The original source signatures could depend on surrounding section variables. These implicit section parameters have now been materialized from Lean's trusted telescope, preserving the original written binders and proposition. A separate trusted comparison process elaborates the original and materialized declarations, aligns their universe parameter lists, and calls `Kernel.isDefEqGuarded` on the types. The original reference proof is then replayed under the materialized signature without comparison helpers. The comparison source and results are private evidence. This avoids relying on pretty-printed type strings or hygiene-sensitive expression hashes as equality checks.

`premise_context` contains the complete predecessor source plus required universe declarations, excluding evaluator target-absence assertions, with one exception: where an earlier proof matched the target's private reference up to whitespace in at least 15 characters, it is shown as the neutral placeholder `/- proof omitted -/`, keeping its declaration's statement and attributes. Rows 417-424 of the amendment log (2026-10-12) record this for 8 tasks: `lib_algebra_groups_pilot_group_basic_02`, `_06` and `_08`, `lib_analysis_inequalities_main_convex_function_06`, `_08` and `_10`, and `lib_sets_logic_main_equiv_basic_04` and `_10`; in `equiv_basic_10` only the `right_inv` proof field of the definition `subtypePreimage` is replaced. `premise_context` is display-only and never compiled, so it need not be valid Lean; the Lean inputs and `verification_request_hash` are unchanged, and the 8 references were re-verified with identical metrics. The 68 task rows changed by rows 417-484 are kept in their earlier form in `data/private/tasks-before-answer-access-and-audit-amendment.json`. This gives models coherent local definitions, notation and scopes. It includes earlier library proofs, and no task's reference proof now occurs in its own prompt as an exact match of 15 or more whitespace-normalized characters. Shorter exact matches and near-verbatim sibling proofs remain for the pending human answer-access audit: the 14-character reference `dite_eq_left h` of `lib_sets_logic_main_equiv_basic_09` occurs in the `invFun` field of `subtypePreimage`, the prompt of `equiv_basic_10` still shows the preceding dual lemma `subtypePreimage_symm_apply_coe_pos` with its proof `dite_eq_left h`, and sibling proofs one or two tokens away from the reference remain, for example in `lib_algebra_groups_main_units_basic_08` and `lib_number_theory_main_numbertheory_divisors_02`. The largest trusted library prefix is under 7 KB. The same fixed bytes are used for every condition. The earlier excerpt policy is preserved in the amendment log and `library-before-premise-context.jsonl`; this prompt-only revision did not change runtime imports, signatures, contexts or proof bodies.

## Authored tasks and novelty

The 60 authored statements combine assumptions or ask related consequences, with a short rationale in each provenance record. They are not generated by renaming a theorem or substituting a sequence of constants. They include algebraic consequences, divisibility and remainder combinations, real inequalities, set and logic constructions, linear maps and finite sums/products.

“Fresh” here means authored for this collection. It is **not** a claim that an equivalent statement is absent from Mathlib, public mathematics or model training data. Exact/equivalent-statement screening remains part of the answer-access audit. Many tasks are easy controls and use existing automation effectively.

## Sampling and family limitations

The library collection starts from early suitable declarations in 20 selected source modules. It is not a random sample of Mathlib and does not yet meet a defensible depth/length stratification. Source-length strata and authored-task difficulty labels are provisional; measured reference depth and length must inform the final strata before model outcomes are available.

Library families initially group source modules; authored families identify the construction used. Independent review led to replacement of two smoke problems and one main problem with construction overlap across pilot/main, replacement of two library aliases whose equivalent theorem was already available, and merging of related main-task families. The new conditional-monoid smoke problem is grouped with its related pilot library family. These changes precede model generation and are recorded with prior tasks/proofs in `data/private/dataset_amendments.jsonl`. Its rows 227-541, added on 2026-10-12 and also before model generation, hold the retroactive context records (227-416), answer-access premise amendments (417-424), authored audit annotations (425-484) and archived-index corrections (485-541) described above.

Module separation alone cannot establish complete separation of related constructions. Broader cross-module and authored/library review remains pending, so `family_reviewed` remains false. Two merged main families cross domains: `main_two_step_discrete_gap` (`number_theory`, `linear_algebra_combinatorics`) and `main_injective_first_coordinate` (`sets_logic`, `linear_algebra_combinatorics`). Domain-stratified family resampling is appropriate only when the final families are nested within domains. Report the eventual number of independent families, not only 250 task rows.

The pilot may guide runtime, extraction and precision decisions. Do not tune task replacements or family groupings using main-model outcomes. Archive every preprocessing correction and pre-evaluation exclusion with its reason.

## Python interface

`load_tasks(path)` reads JSONL or a JSON task array (also accepting an object with a `tasks` array). `validate_manifest(tasks, enforce_quotas=False)` returns a list of structural errors; it does not raise on ordinary validation failures or assert Lean correctness. With `enforce_quotas=True`, it checks the complete 50/200, domain and main-origin quotas.

`validate_references(tasks, references)` checks the one-to-one private reference mapping. `readiness_errors(tasks)` returns unresolved readiness gates. Hash checks cover trusted context, premise excerpt, binders and proposition. Recompute these hashes only after an intentional, recorded revision.

`readiness_errors` never reports an empty manifest as ready. `validate_references` lists reference rows that are not objects with a string `task_id` instead of raising. `reference_in_prompt(task, proof)` reports whether a private proof's whitespace-normalized text occurs, at any length, in a prompt rendered by `prompts.messages()`, and returns `None` when it cannot run (no proof text, or a task that cannot be rendered). `answer_access_errors(tasks, references)` flags each task whose matching reference proof has at least `ANSWER_ACCESS_MIN_CHARS` (15) normalized characters, and `validate-dataset --references` adds these flags to `readiness_errors`. In the readiness report, the `reference_proofs_absent_from_prompts` gate stays pending while any task is flagged or unchecked; `answer_access_screen` lists those tasks and, as `short_exact_match_task_ids`, exact matches of `SHORT_EXACT_MATCH_MIN_CHARS` (9) to 14 characters, which do not block the gate. Per-task `reference_proof_in_prompt` reports matches of any length. The JSONL readers end records only at line breaks (`\n`, `\r\n` or `\r`), so raw U+2028, U+2029 and U+0085 inside strings are preserved; decode errors cite `path:line`.

The structural validator detects duplicate task IDs, unsafe target/module names, malformed or reordered import descriptors, cross-split family IDs, accidental public reference fields, direct import of a target module, missing/incorrect quota counts, exact source signature duplicates and stale content hashes. It cannot determine logical equivalence, prove absence from pretraining or replace the Lean validity gate.
