Mathematical compression in Lean: reproducible analysis companion¶

Summary¶

The final 128,000-token cohort contains 3,831 accepted proofs among 9,600 attempts. Under the standard prompt, Fable has the highest observed yield (77.0%), followed by Astra (75.25%); this does not by itself resolve nearby model ranks. Conditional T₀ comparisons favor Fable over Astra on shared solved questions, while Fable versus Opus remains inconclusive. Source-length associations change sign when parse failures are excluded.

This executed notebook independently checks the key statistics from the bundled observations. It makes no provider, Lean, or cloud calls. The separate report app and scientific paper provide the narrative; the code and saved outputs here support inspection and rerunning.

Context and methods¶

The main corpus has 100 selected lemmas from 19 problem families, eight pinned models, three prompt conditions and four samples per cell. Analysis is post hoc and exploratory. The original prompt contrasts remain primary; the later joint reliability-plus-T₀ contest is supplemental and is not the original paper metric.

Key assumptions¶

  • Family blocks are resampled jointly across models and prompts, retaining every question in a selected family. Estimates remain question-weighted despite unequal family sizes. The corpus is curated, not a probability sample of mathematics.
  • Conditional compression excludes failed or unmeasurable proofs; supports vary by pair. A failed proof is never assigned compression zero.
  • The 8,192- and 128,000-token cohorts have identical paired question/prompt designs but separate generations. Output cap, OpenAI processing tier and streaming transport differ; cross-run changes are not an isolated causal cap effect.
  • Acceptance uses the frozen strict submission interface. Prose/Markdown surrounding a proof can fail parsing; the notebook does not repair or regrade any response.
  • T₀ can reflect typeclass/library expansion. It is not automatically a measure of the informativeness of a mathematical argument.

Results¶

1. Reproduce standard-prompt success and family intervals¶

The code below reconstructs per-question yields and resamples family blocks. It reproduces the original deterministic random stream: question-bootstrap draws are allocated first, followed by family draws. No attempt-level independent-observation interval is used.

df = observations[observations.run == "cap128000"].copy()
tasks = sorted(df.task.unique())
family_by_task = metadata.set_index("id").family.reindex(tasks)
families = sorted(family_by_task.unique())
assert len(tasks) == 100 and len(families) == 19
family_matrix = np.array([[int(family_by_task.loc[t] == f) for t in tasks] for f in families])
rng = np.random.default_rng(SEED)
question_weights = rng.multinomial(100, np.full(100, .01), size=REPLICATES)
family_draws = rng.multinomial(19, np.full(19, 1/19), size=REPLICATES)
family_weights = family_draws @ family_matrix

def family_summary(values):
    values = np.asarray(values, float)
    available = np.isfinite(values)
    numerator = family_weights @ np.where(available, values, 0)
    denominator = family_weights @ available.astype(float)
    estimates = numerator[denominator > 0] / denominator[denominator > 0]
    return float(values[available].mean()), *np.quantile(estimates, [.025, .975]), int((denominator == 0).sum())

2. Independently reproduce three conditional T₀ matchups¶

For each shared solved question, every valid proof from one model is paired with every valid proof from the other. Higher exact rational T₀ earns one point, an exact tie earns one-half. Pairings are averaged within question, then questions receive equal weight. These reused proof pairings are not independent statistical observations.

3. Reproduce the source-length sensitivity¶

The coefficient is the pooled within-cell covariance divided by within-cell variance, after demeaning log₂ source characters and acceptance inside model × question × prompt cells. It is not an equal-question mean causal effect. Family bootstrap weights apply to the resulting question-level sufficient statistics.

reviewed_length = json.loads((ROOT / "tables/main/source_length_associations.json").read_text())
length_rows = []
for exclude_format in [False, True]:
    sample = df[(df.completed == 1) & (df.sourceNonWhitespaceCharacters > 0)].copy()
    if exclude_format: sample = sample[~sample.status.isin(["parse_failure", "output_format_failure"])]
    sample["x"] = np.log2(sample.sourceNonWhitespaceCharacters)
    grouping = sample.groupby(["model", "task", "condition"])
    sample["xr"] = sample.x - grouping.x.transform("mean")
    sample["yr"] = sample.valid - grouping.valid.transform("mean")
    sample["xy"] = sample.xr*sample.yr; sample["xx"] = sample.xr**2
    totals = sample.groupby("task")[["xy", "xx"]].sum().reindex(tasks, fill_value=0)
    coefficient = totals.xy.sum()/totals.xx.sum()
    denominator = family_weights @ totals.xx.to_numpy()
    boot = (family_weights @ totals.xy.to_numpy())[denominator > 0]/denominator[denominator > 0]
    low, high = np.quantile(boot, [.025, .975])
    population = "completed_excluding_format" if exclude_format else "completed"
    expected = next(r for r in reviewed_length if r["population"] == population and r["condition"] == "all")
    np.testing.assert_allclose([coefficient, low, high], [expected["slope_probability_per_doubling"], expected["ci_family_low"], expected["ci_family_high"]], atol=1e-12)
    length_rows.append({"Population": "Exclude parse/format failures" if exclude_format else "All completed nonempty", "Submissions": len(sample),
        "Slope (pp per doubling)": coefficient*100, "Low": low*100, "High": high*100})

Takeaways and replay instructions¶

  1. Separate scheduled success, completion and acceptance among completed responses. Their denominators are different.
  2. Compare T₀ only on explicit shared measurable supports and retain uncertainty. Failure is missing compression, not zero compression.
  3. Formatting adherence and dependency expansion affect interpretation. The observed metrics are not interchangeable with mathematical ability.
  4. Treat the cross-run comparison as observational. The cap, processing tier and transport changed together; the 960-attempt smoke test is separate descriptive evidence.

For full statistical replay, use reproducibility/reproduce.py primary or reproducibility/reproduce.py cross-run from a Python environment matching reproducibility/requirements.txt. Both refuse an existing output directory. Original analysis source files are copied byte-for-byte. The cross-run loader consumes the audited normalized CSV instead of private raw provider records; it validates joins against the exact comparison DTOs and then runs the original statistical functions unchanged. Full API/SSE provenance and Lean verification audits require the original private evaluation store and are intentionally not rerun here.
